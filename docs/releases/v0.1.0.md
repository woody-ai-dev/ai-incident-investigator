# v0.1.0 — Evidence-backed incident investigation MVP

AI Incident Investigator helps an on-call engineer turn service telemetry into a
report with findings, hypotheses, evidence references, recommended checks, and
explicit data gaps.

This first release provides a reproducible local demo. A Spring Boot order
service generates a controlled payment timeout; the Python backend collects its
telemetry, and a React interface submits and presents the investigation.

## Included

- JSONL log collection filtered by service, environment, and incident window.
- Historical Prometheus summaries for scrape availability, JVM heap, and a
  cumulative HTTP 504 counter.
- Current Spring Boot Actuator identity and health snapshots, clearly separated
  from historical observations.
- Optional OpenAI structured analysis with request-specific evidence-ID
  constraints and evidence-preserving failure handling.
- React/TypeScript UI with validated inputs, evidence flow, linked findings,
  source context, and JSON export.
- Docker Compose demo that works without API credentials; an explicit override
  enables billable live model analysis.
- Python, frontend/browser, Java, and Compose checks in GitHub Actions.
- Synthetic offline evaluation and a bounded, opt-in real-model evaluation
  runner with checkpoints and review questions.
- Editable architecture diagram and documented demo/release procedures.

## Validation

See the [validation record](https://github.com/woody-ai-dev/ai-incident-investigator/blob/v0.1.0/docs/validation/2026-10-16.md) for actual checks,
real-model observations, and limits. Passing technical checks does not establish
that every model conclusion is correct. The small recorded scenario set is not
a production accuracy benchmark.

## Scope and known limitations

- Local demo without authentication, service discovery, or persistent
  investigation history; APIs and report formats may change before 1.0.
- Investigation starts on request. There is no continuous monitoring,
  automatic remediation, deployment, or on-call notification.
- One active local JSONL source, three fixed Prometheus queries, and one
  configured Actuator target. Traces are not connected.
- Prometheus queries cover at most one hour. Counters are cumulative, not the
  number of failures in the requested window.
- Actuator `UP` reports current endpoint state; it does not prove historical
  health or successful business operations.
- Valid citations do not guarantee valid reasoning. In the real UI check, the
  model overstated service availability and heap stability. An engineer must
  review conclusions and recommended actions against the original evidence.
- Live analysis sends the supplied request and collected telemetry to OpenAI
  and uses the configured account's API billing.
