### Issues found during development

Earlier runs exposed unsupported causal conclusions and an invented evidence ID
`_missing_`. The report validator correctly rejected the unknown reference and
retained collected evidence. The adapter was then changed to bind all three
reference fields to request-specific native JSON Schema enums and enforce the
same membership rule locally. Sixteen regression tests cover schema constraints,
independent requests, and SDK request/response behavior using mock transport.

Prompt refinements distinguish recorded symptoms from underlying causes,
simulated events from real-fault evidence, cumulative counters from window
counts, current endpoint status from historical business health, and retained
data searches from future instrumentation. Valid citation IDs still do not
prove that the cited content supports a statement.

The final recorded outputs received this Codex-assisted rubric review. Each
criterion ranges from 0 to 2; these are notes on three outputs, not an accuracy
percentage.

| Scenario | Evidence support | Causal reasoning | Data limitations | Next checks |
| --- | ---: | ---: | ---: | ---: |
| Full evidence, simulated timeout | 2 | 2 | 2 | 2 |
| Partial source outage | 2 | 2 | 2 | 1 |
| Current health only | 1 | 2 | 2 | 2 |

Two wording concerns remain in those original outputs:

- The partial-source case recommends checking whether the event was real or
  simulated, although its log already marks it simulated. A useful follow-up
  would check for **additional real failures**.
- The current-health-only summary adds “and no errors” after `UP`/HTTP 200.
  Those responses do not establish the absence of business errors. The detailed
  findings do retain the snapshot timestamp and historical limitation.

No response was edited to improve the apparent result. A fresh end-to-end run
on a later prompt or code revision is a separate observation, not a retroactive
correction to these outputs.

## What these checks do not establish

- The four known scenarios were also used during prompt refinement. They are
  not a held-out dataset or evidence of general incident-diagnosis accuracy.
- One final repetition does not measure output stability.
- `UP` is endpoint status at an observation time, not proof of successful orders.
- A controlled timeout is not a real payment-provider outage, network delay,
  or automatically reproduced production fault.
- This MVP does not monitor continuously, repair code, open pull requests,
  deploy changes, or notify an on-call engineer.
- Local checks do not substitute for GitHub CI on the published commit.
