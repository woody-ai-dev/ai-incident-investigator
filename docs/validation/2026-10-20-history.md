## Behavior verified

- A successful POST with persistence exposes its UUID and saved-report link while
  retaining the original report JSON contract. Nonpersistent reports remain usable.
- History lists summaries rather than full evidence payloads. Ordering uses UTC
  creation time and UUID, preserving microseconds and ties between records.
- Inclusive/exclusive creation-date boundaries, timezone normalization, combined exact
  filters, empty results, invalid queries/cursors, and storage errors are covered.
- Inserting a newer record between pages does not duplicate or shift older results.
- The migration from `0001_investigations` to `0002_history_index` preserves existing
  snapshots; Alembic's schema check finds no pending model changes on either database.
- Filter/page URLs, Back/Forward navigation, reset of unapplied draft filters,
  invalid date ranges, saved-page reload, safe error messages, and read retries work.
- Stale read responses are discarded; navigation aborts reads and stalled reads time out.
- Opening saved history does not repeat collection or model analysis. Tests with fake
  analyzers confirm that read requests leave their invocation counts unchanged.
- A real saved report remained identical after backend and frontend container recreation.
- Existing evidence inspection, JSON export, last-report fallback, floating selectors,
  mouse/keyboard source highlighting, and strict production CSP checks continue to pass.
- On a narrow viewport, history rows use cards and both history and detail pages avoid
  horizontal body overflow. Summary/model text is rendered as text.

## Reproduce

Run the ordinary Python/frontend checks described in [UI development](../ui-development.md)
and the PostgreSQL tests described in [persistence](../persistence.md#test-databases).
For the real browser checks, start the persistence overlay and run from the repo root:

```bash
docker compose -f compose.yaml -f compose.persistence.yaml up --build --wait --wait-timeout 180
npm --prefix frontend run test:e2e:compose
npm --prefix frontend run test:e2e:history
```

Token accounting, detailed source collection statuses, authentication, background
workers, traces, RAG, and remediation remain outside this change.

## UI follow-up — 2026-10-21

History filters now reuse the floating `SelectField` component, with All entries,
configured demo targets, current-page historical values, and retained URL selections.
Menus support keyboard selection, Escape, internal scrolling, and one open selector
at a time without moving the date fields. All entries map to empty filter values,
including native form serialization. Date inputs share the main investigation form's
control style and normal font weight. The saved-report back link has an 18 px bottom
margin before the title.

The Report node now starts neutral, has a blue outline while a request is pending,
and gets a blue fill when a report arrives. Failed and stopped requests return it to
neutral. A received report can still contain missing evidence or failed LLM analysis.

Verification: 83 frontend unit tests, 11 production-build browser scenarios, and three
real Compose browser checks passed. TypeScript, ESLint, Prettier, Vite and the frontend
Docker build passed. Browser checks compare actual date-control styles between the two
pages and cover selection/reset, URL restoration, title spacing, and Report node states.
The updated frontend container was started against the existing local backend and DB;
no real model requests were made.
